數據欄位映射邏輯 — 基準參考

本文件為 PPOV Extractor 的「PDF 文字 → 結構化欄位」映射邏輯唯一基準來源（Single Source of Truth）。後續任何提取規則、關鍵字、欄位命名或回退邏輯的更動，都應以本文件為對照基準，並同步更新文件。文件涵蓋 config.json 的欄位規則、main.py 的四種提取方法與單位偵測，以及下游匯出流程。

基準版本：v1.9.5（git commit fc60ec5） 文件日期：2026-08-05 欄位數：41 個設定欄位 + 2 個系統欄位 已驗證：6/4 與 8/5 匯出 SHA256 一致

1總覽與資料流

從 PDF 檔到最終 Excel／JSON 的完整資料流，映射邏輯發生在「文字 → 紀錄」階段。

PDF 檔案pdfplumber 逐頁擷取
→
全文文字各頁以換行符串接
→
規則引擎config.json 41 條規則 + 4 種方法
→
結構化紀錄43 個鍵值對（JSON）
→
匯出Excel 總表／JSON ／前端渲染

處理流程（extract_data_from_pdf, main.py:572）

1. 讀取 PDF：pdfplumber 將所有頁面 extract_text() 以 "\n" 串接成 full_text
2. 偵測 保壓壓力單位：detect_checked_unit() → kg/cm² 或 bar
3. 初始化 紀錄：{ "檔案名稱": xxx.pdf, "_單位_保壓壓力": ... }
4. 遍歷 config["fields_to_extract"] 每條規則：
   - 依 extraction_method 從 EXTRACTION_MAPPING 查表取得函式
   - 有 parameters 時傳入（並附加 checked_unit）
5. 回填 每個欄位的提取結果到紀錄
所有提取函式的共同回退值為 "未找到"；表格類數值允許的佔位值為 NCA / NAC / N/A。

2映射架構

映射完全由 config.json 驅動（設定驅動），程式碼不含任何寫死的欄位規則。

規則結構（config.json → fields_to_extract[]）

{
  "name": "保壓壓力_目標值",          // 輸出欄位名稱（資料鍵）
  "keywords": ["保壓壓力 HOLD PRESSURE"], // 優先序關鍵字（中文在前、英文在後）
  "extraction_method": "find_table_value", // 方法名，經 EXTRACTION_MAPPING 查表
  "parameters": {                  // 選擇性
    "column": "目標值",                  // 宣告欄（目前僅供標示，不參與邏輯）
    "value_type": "target"               // 決定取哪個索引值
  }
}

方法分派表（EXTRACTION_MAPPING, main.py:228）

方法名稱對應函式用途目前使用數
find_text_aftermain.py:21"Key: Value" 格式的基本欄位10

4find_text_after（Key: Value 格式）

用於基本欄位：在全文行中尋找關鍵字，取出關鍵字「之後」的內容。適用 "關鍵字: 值" 版面。

演算法（main.py:21）

對每個 keyword（依 config 順序，找到即回傳）：
  ▸ 方法一：逐行掃描
    1. 找到含關鍵字的行 → 取關鍵字之後的文字
    2. clean_val() 清理：
       - 移除單位首碼，如 "(℃ / hr)"、"(J/hr)"
       - 移除前導冒號／半形／全形空格
    3. 同行為空 → 看下一行，若下一行開頭不是黑名單
       （產品／模具／射出／原料／圖面）則取用
  ▸ 方法二：正則捕捉（後備）
    keyword \s*[:：]?\s* ( [^\n\r]+ )   → 取 group(1) 並清理結尾空白
  ▸ 全部失敗 → 回傳 "未找到"

特性與注意事項

  • 多個關鍵字是「OR」關係，依 config.json 內順序嘗試；中文關鍵字優先於英文。
  • 「同一行後方無內容時取下一行」會跳過以 產品／模具／射出／原料／圖面 開頭的行（防止誤取隔壁區塊標題）。
  • 單位首碼正則：^\s*\([J℃\w]\s*/\s*\w+\)\s*（大小寫不敏感）。
  • 適用欄位：產品型號、產品名稱、圖面版次、模具編號、模具穴數、射出成型機編號、射出成型機噸數、螺桿尺寸、螺桿形式、烘料條件（共 10 欄）。

5find_material_number（原料料號專用）

專為「原料料號」設計的強化版提取，處理料號可能出現在關鍵字前、後或上下行的多種版面。

演算法（main.py:158）

對每個 keyword：
  1. 同關鍵字行後方文字（去除冒號空白）→ 若非「原料資訊/Material Information」即回傳
  2. 下一行（非黑名單開頭）→ 回傳，並清除「原料資訊/Material Information」字首
  3. 若下一行恰為「原料資訊」→ 檢查再下一行
  4. 關鍵字前方文字 → 由後往前取 1~2 個詞組，
     需同時含字母與數字（料號特徵）才回傳
  5. 上一行（關鍵字前方為空時）→ 同樣需含字母＋數字
  6. 正則捕捉 keyword \s*[:：]?\s* ([^\n\r]+)（後備）
  ▸ 全部失敗 → "未找到"
黑名單開頭比 find_text_after 多兩項：烘料、螺桿。料號判定特徵為「含字母且含數字」。

6find_table_value（表格參數 — 核心方法）

處理 目標值／下限值／上限值／實際值 四欄結構的表格參數，是目前使用最多的方法（30 個欄位），也是歷次修正重點。

關鍵參數

參數意義值
value_type決定取第幾個 token（唯一實際參與邏輯的參數）target=0 / low=1 / high=2 / actual=3
column宣告用欄位名（不參與邏輯，見第 14 節）目標值／下限值／上限值／實際值
checked_unit由引擎附加傳入（目前未使用，見第 14 節）kg/cm² / bar

演算法（main.py:92）

對每個 keyword：
  逐行掃描，找到含關鍵字的行 i

  # 優先掃描視窗：[i, i+1, i-1, i+2, i-2, i+3]
  search_indices = [i, i+1, i-1, i+2, i-2, i+3]

  # 單值參數判定（關鍵字含以下任一 → 視為單值）
  is_single_param = keyword 含 CYCLE / TONNAGE / SCREW DIA / MOLD CYCLE

  # ── Phase 1：多 token 表格列 ──
  對視窗內每一行：
    tokens = 正則 \b\d+\.?\d*\b | NCA | NAC | N/A  (不分大小寫)
    若 tokens==6 且行含 '/' → 兩兩合併成 3 個 "a / b" token
       （例："155 / 2269 150 / 2196 160 / 2342"）
    若 tokens ≥ 3 且 非單值參數：
        target → tokens[0]   low → tokens[1]
        high   → tokens[2]   actual → tokens[3]

  # ── Phase 2：單值參數後備（僅 target）──
  僅當 value_type == "target" 時：
    Case A：關鍵字同一行後方第一個數字 token
    Case B：視窗內某行「恰有 1 個 token」，且該行不含
            衝突關鍵字（FILL/SHOT/PACKED/CLAMP/TONNAGE/CYCLE/MOLD，
            自身關鍵字內含者除外）

  ▸ 全部失敗 → "未找到"

實際範例（保壓壓力 155 / 2269）

PDF 行內容：  保壓壓力 HOLD PRESSURE  155 / 2269  150 / 2196  160 / 2342
tokens:      ["155","2269","150","2196","160","2342"]  → 6 個且含 '/'
合併後:      ["155 / 2269", "150 / 2196", "160 / 2342"]
  target → "155 / 2269"     low → "150 / 2196"    high → "160 / 2342"

注意事項

  • 視窗設計目的：數值可能位於關鍵字行、下一行（常見）或上一行；視窗覆蓋 ±3 行內的可能位置。
  • 單值參數（週期時間、鎖模力等）僅有 1 個數值，若不排除會被 Phase 1 誤抓相鄰表格列的第一個數字 → 以 is_single_param 切換到 Phase 2 的嚴謹單值判定。
  • 6 token 斜線合併：PDF 表格常把「目標 155/2269」拆成兩行數字，此規則將其還原為成對值。
  • NCA／NAC／N/A 視為合法數值 token（保留原文，不回退）。

7find_nested_value（已註冊、未使用）

處理「大標題 → 子標題 → 值」的巢狀結構，目前已註冊於分派表但 config.json 中沒有欄位使用。

pattern = main_keyword .*? sub_keyword \s*[:：]?\s* (\S+)   (re.DOTALL)
主關鍵字與子關鍵字所有組合逐一嘗試，成功即回傳
若要新增此類欄位，直接在 config.json 加入帶 parameters.sub_keywords 的規則即可，無需改程式。

8單位偵測（detect_checked_unit, main.py:555）

保壓壓力單位由 PDF 上的勾稽方塊（□／■）決定，結果寫入系統欄位 _單位_保壓壓力。

PDF 版面結果
□ Bar  ■ kg/cm2kg/cm²
■ Bar  □ kg/cm2bar
無勾稽方塊或無法判定kg/cm²（預設）

判定規則

  • 逐行尋找同時含 □ 與 ■ 且含 Bar 的行。
  • ■ kg 或 ■kg → kg/cm²；■ Bar 或 ■Bar → bar。

10命名慣例

表格參數欄位名（輸出鍵）

規則

  • 輸出鍵 = 參數名 + 後綴；參數名與 config.json 的 keyword（中文部分）對應。
  • 系統欄位以 _ 開頭（_單位_保壓壓力），與業務欄位區隔。
  • 匯出 Excel 時欄位順序 = ["檔案名稱"] + config 順序（app.py:486），config.json 中的順序即為輸出欄位順序，新增欄位時請在「同參數群組」內插隊以保持版面。

11回退值與特殊值

值產生情境說明
"未找到"所有方法的最終回退任何方法都取不到值時的字串回退值
NCA / NAC / N/A表格方法 token 解析視為合法數值 token 原樣保留（代表規格未定義）
