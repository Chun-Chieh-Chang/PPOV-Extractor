# Information Disclosure via Detailed Error Messages

**ID:** vuln-0003
**Severity:** MEDIUM
**Found:** 2026-08-02 12:17:47 UTC
**Target:** http://host.docker.internal:5000
**CWE:** CWE-209
**CVSS:** 5.3
**Fix Effort:** Trivial

## Description

The application returns detailed error messages including internal implementation details, SQL queries, and exception traces in client responses.

## Evidence

404 response:
{"error": "Resource not found", "details": "404 Not Found: The requested URL was not found on the server."}

500 response exposes internal error details.

## Impact

Detailed error messages assist attackers in understanding application structure, database schema, and input validation logic for targeted attacks.

## Technical Analysis

Error handlers expose internal details. The details field leaks internal information to clients.

## Proof of Concept

1. Request non-existent resource to trigger 404
2. Request invalid document ID to trigger error handling
3. Observe detailed error messages with internal information

```
import requests
import jwt

SECRET = "super-secret-jwt-key-123"
token = jwt.encode({"user_id": 1, "username": "testuser"}, SECRET, algorithm="HS256")
headers = {"Authorization": f"Bearer {token}"}

# Trigger 404
resp = requests.get("http://host.docker.internal:5000/api/nonexistent", headers=headers)
print(f"404 Response: {resp.json()}")

# Trigger 500
resp = requests.post("http://host.docker.internal:5000/api/extract",
    json={"file_content": None},
    headers=headers)
print(f"500 Response: {resp.json()}")
```

## Remediation

1. Return generic error messages to clients
2. Log detailed errors server-side only
3. Remove 'details' field from error responses
4. Implement proper error handling without exposing internals

## Assumptions

None - this is a configuration issue present in all environments.
