# Reflected Cross-Site Scripting (XSS) in Extract Endpoint

**ID:** vuln-0004
**Severity:** MEDIUM
**Found:** 2026-08-02 12:18:27 UTC
**Target:** http://host.docker.internal:5000/api/extract
**CWE:** CWE-79
**CVSS:** 4.6
**Fix Effort:** Low

## Description

The /api/extract endpoint reflects user-supplied content directly in the JSON response without sanitization, enabling reflected XSS if consumed by vulnerable frontend applications.

## Evidence

POST /api/extract with payload `<script>alert('XSS')</script>`:
- Status: 200
- Response contains payload: true
- Payload reflected in extracted_text field

## Impact

If extracted content is rendered in a web interface without proper output encoding, attackers can inject malicious JavaScript to steal sessions, perform actions on behalf of victims, or redirect users.

## Technical Analysis

The extract endpoint stores and returns user input without HTML escaping. The content is returned directly in JSON without sanitization.

## Proof of Concept

1. Send POST to /api/extract with XSS payload in file_content
2. Observe payload reflected in JSON response
3. If frontend renders content with innerHTML, script executes

```
import jwt
import requests

SECRET = "super-secret-jwt-key-123"
token = jwt.encode({"user_id": 1, "username": "testuser"}, SECRET, algorithm="HS256")
headers = {"Authorization": f"Bearer {token}", "Content-Type": "application/json"}

xss_payload = "<script>alert('XSS')</script>"
resp = requests.post("http://host.docker.internal:5000/api/extract",
    json={"file_content": xss_payload},
    headers=headers)
print(f"Status: {resp.status_code}")
print(f"Payload reflected: {xss_payload in resp.text}")
```

## Remediation

1. Sanitize user input before storing in database (HTML escape)
2. Implement output encoding when rendering content in frontend
3. Add Content-Security-Policy headers
4. Use whitelist of allowed characters for content

## Assumptions

The extracted content is displayed in a web interface without proper output encoding.
